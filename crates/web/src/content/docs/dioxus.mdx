Run [Dioxus](https://dioxuslabs.com) components on a Wove tree.
You write RSX, and signals update the screen.

```toml
[dependencies]
wove = { git = "https://github.com/arocomputer/wove" }
wove-dioxus = { git = "https://github.com/arocomputer/wove" }
dioxus = { version = "=0.7.10", default-features = false, features = ["macro", "hooks", "signals"] }
futures-lite = "2"
```

```rust
use dioxus::prelude::*;
use wove::{Event, Key};
use wove_dioxus::{elements as dioxus_elements, View};

fn app() -> Element {
    let mut name = use_signal(String::new);
    rsx! {
        view { direction: "column",
            text { content: "Your name?" }
            input {
                value: "{name}",
                oninput: move |event| name.set(event.data.to_string()),
            }
            text { content: "Hello, {name}!" }
        }
    }
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut view = View::new(VirtualDom::new(app))?;
    view.focus_next(false)?;
    let quit = |event: &Event| *event == Key::Escape.into();
    futures_lite::future::block_on(wove_dioxus::run(&mut view, quit))?;
    Ok(())
}
```

`wove_dioxus::run` handles terminal input and repaints when a signal changes.
Bring your own executor. Like the core, it binds no quit key.

## Tags

| Tag | Core element | Attributes |
| --- | --- | --- |
| `view` | `Container` | |
| `panel` | `Panel` | `style` |
| `text` | `Text` | `content`, `wrap`, `style` |
| `rich` | `RichText` | `spans`, `wrap` |
| `input` | `Input` | `value`, `placeholder`, `style` |
| `textarea` | `Textarea` | `value`, `placeholder`, `style` |
| `scroll` | `Scroll` | |
| `lazy` | `Lazy` | `follow` |
| `list` | `List` | `rows`, `selected` |
| `table` | `Table` | `columns`, `rows`, `selected`, `style` |

Use `content` for a block of text. Bare strings in RSX become separate `text`
elements, one per string.

There is no `feed` tag. A `lazy` of `text` children covers the same case and
updates by key.

## Layout

Every tag accepts `width`, `height`, `grow`, `gap`, `padding`, and `direction`
(`row` or `column`). Numbers are cells.

For anything else, pass a full core layout:

```rust
use wove_dioxus::AttributeValue;

rsx! { text { layout: AttributeValue::any_value(my_layout) } }
```

Use either `layout` or the individual attributes on one element, not both.

## Events

| Listener | Receives |
| --- | --- |
| `onkey`, `onpaste`, `onmouse` | The core `wove::Event` |
| `oninput` | The new value, after an edit |
| `onselect` | The new row index of a `list` or `table` |

Call `prevent_default` to stop the element's own behavior, and
`stop_propagation` to stop parent listeners. Keys only reach focused elements
and their parents. Nothing is focused at start, so call `view.focus_next` or
let the user press Tab.

## Controlled inputs

Bind a signal to `value` and set it from `oninput`, as in the example above.
The input keeps its cursor and undo history as long as the value you pass back
matches its text.

## Custom tags

Register your own elements with `Registry::register`, then create the view with
`View::with_registry`. Hyphenated tag names work without a schema. See the
[adapter tests](https://github.com/arocomputer/wove/blob/main/crates/dioxus/tests/view.rs)
for an example.

## Without a terminal

`view.frame(width, height)` applies pending updates and returns a frame.
`view.send(event)` dispatches input. Use these for tests or your own loop.
