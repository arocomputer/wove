A session owns the terminal while it runs. `Terminal` acquires raw mode, enables
the input modes the application asks for, draws frames, and restores the terminal
however the process ends. `terminal::run` wraps the common case; a custom loop
uses the same pieces directly.

## Choose a screen

`ScreenMode::Alternate` (the default) draws on the alternate screen, a
full-screen buffer the terminal restores on exit. `ScreenMode::Main` draws over
the main screen without the alternate buffer. `ScreenMode::Inline` grows frames
downward from the launch cursor and leaves finished rows in the terminal's own
scrollback.

`Terminal::with_options` also chooses which input modes to enable: mouse
reporting, pointer motion, bracketed paste, focus reports, and unambiguous key
reports. Motion is off by default, because a moving pointer sends hundreds of
reports a second. Turn `mouse` off to leave text selection to the terminal.
`Terminal::switch` moves between an inline session and a full-screen view while
running; the main screen keeps what the inline session drew while the alternate
screen is up.

## Draw a frame

`Tree::frame` recomputes layout after an update or a resize and otherwise returns
the cached frame, so an idle loop that draws every iteration costs nothing.
`Renderer` writes changed cells and the cursor position as one synchronized
update, and maps colors to the `Depth` the terminal accepts. A full-screen frame
matches the terminal's dimensions; an inline frame matches its width and may be
of any height.

The terminal belongs to the session. An application that prints around a live
session must call `Terminal::invalidate` afterwards, or the next frame diffs
against physical contents that are gone and leaves stale cells.

## Own the loop

`terminal::run` is a blocking convenience loop on the alternate screen. It ends
when its callback returns false; the library binds no quit key, so handling one
is the application's decision. It draws, waits for input, dispatches, and
repeats.

An application with timers, background work, or its own screen choice builds its
loop from the same parts. `read` returns the next event, and `poll` waits for
input with a timeout. `convert` turns a backend event into a portable one for an
application that already owns its input source. `Terminal::draw` takes the frame
and `Terminal::size` reports the current dimensions after a resize.

The library provides no wakeup channel: `poll` waits for terminal input, so a
loop that also runs timers or awaits background work gives `poll` a timeout and
checks its own schedule, or receives work on a channel and draws when it arrives.
Drawing more often than the content changes costs nothing, because an unchanged
frame is skipped before any cell is compared.

Dispatch every event through `Terminal::to_frame` first when the session is
inline, and handle the events from `Terminal::typed_ahead` before reading more
input.

## The startup probe

A session asks the terminal once, as it starts, what it supports and where its
cursor is. `Terminal::capabilities` holds the answers: whether kitty key reports
work, in which case `Options::keyboard` takes effect, and the background color,
for choosing a light or dark palette. The request ends with a device-attributes
query that every terminal answers, so the wait does not depend on a timeout.

Keys typed during the probe come back from `Terminal::typed_ahead`; handle them
before reading further input. `terminal::run` and `wove_dioxus::run` process
these events automatically. A terminal that does not report its cursor starts an
inline session on a cleared screen instead of at the shell prompt.

## Output ownership

A `Terminal` is `Send`, so an application that renders on another thread moves
the whole session there and hands it cloned frames; a frame is an owned `Buffer`
and can cross the thread boundary. Input, session state, and output are one
value, so `draw`, `commit`, and `copy` all run on the thread that owns it. The
usual shape is a rendering thread that receives frames and commands over a
channel while the rest of the application builds them.

## Inline sessions

`ScreenMode::Inline` draws on the main screen, starting at the shell's cursor. A
frame may be of any height: ask `Tree::height` for the content's natural height,
then pass it to `frame`. When a frame outgrows the screen its head scrolls into
the terminal's own scrollback and is never rewritten.

```rust
let (width, _) = terminal.size()?;
let height = tree.height(width)?;
terminal.draw(tree.frame(width, height)?)?;
```

An inline frame starts wherever the session began and moves as it scrolls, so a
mouse report's row is not the frame's row. Pass events through
`Terminal::to_frame` before dispatching them; it returns `None` for a report
outside the frame. The `inline` example leaves the mouse off instead, which keeps
the terminal's own selection and scrollback gestures.

`Terminal::commit(rows)` releases finished rows at the top of the last frame.
They stay where they are, and the next frame starts beneath them, so remove their
elements from the tree. This keeps frames small however long a session runs.
Exiting parks the cursor below the output even when every row has been committed,
scrolling a fresh line into view if needed.

A resize clears the visible screen and repaints the current frame; committed rows
that were still visible are gone unless the application draws and commits them
again. This is deliberate: a committed row belongs to the terminal's scrollback,
and the session does not keep a second copy of it. The `inline` example shows the
whole loop.

## Restoration

A panic restores the terminal before its message prints, so the message is
readable. So does a fatal signal such as hangup or terminate, including while the
startup probe is waiting for replies. An inline session parks the cursor beneath
its frame first, so what prints next lands under it. Set `Options::signals` to
false when the application handles signals itself.

`Terminal::stop` suspends the process as Ctrl-Z does in a shell, which raw mode
otherwise turns into an ordinary key. `Terminal::suspend` and `Terminal::resume`
release and reacquire the terminal for a child program. On Windows, call
`Terminal::reassert` when `Event::WindowFocus(true)` arrives: the console drops
input modes while unfocused. Each frame goes out in a single write, so a restore
from another thread cannot land inside one.
