---
title: SSH
description: Serve a Wove app to each SSH connection.
---

SSH runs a separate copy of your app for each person who connects over
SSH. No local terminal is involved.

```toml
[dependencies]
wove = { git = "https://github.com/arocomputer/wove" }
wove-ssh = { git = "https://github.com/arocomputer/wove" }
russh = "0.63"
tokio = { version = "1", features = ["macros", "net", "rt-multi-thread", "signal"] }
```

```rust
use wove::{elements::Text, Tree};
use wove_ssh::{Error, Server};

#[tokio::main]
async fn main() -> Result<(), Error> {
    let host = russh::keys::load_secret_key("host_key", None)?;
    let allowed = russh::keys::load_public_key("id_ed25519.pub")?;

    let server = Server::new(
        host,
        move |_user, key| key == &allowed,
        |peer| {
            let mut tree = Tree::new();
            let hello = format!("Hello, {}!", peer.user);
            tree.add(tree.root(), Text::new(hello))?;
            Ok(tree)
        },
    );

    let listener = tokio::net::TcpListener::bind("127.0.0.1:2222").await?;
    server.serve(listener, async {
        let _ = tokio::signal::ctrl_c().await;
    }).await
}
```

## Try the example

```sh
ssh-keygen -t ed25519 -f /tmp/wove-host -N ''
cargo run -p wove-ssh --example server -- /tmp/wove-host ~/.ssh/id_ed25519.pub
ssh -p 2222 -i ~/.ssh/id_ed25519 guest@localhost
```

Keep the host key private and out of your repository.

## What you supply

- A host key. Wove never creates one, so clients see the same key each time.
- An authorization function. It gets the username and the verified public key.
  Return `true` only for keys you trust.
- A factory that builds the app for each connection. It gets a `Peer` with the
  user, key, address, terminal type, and size.
- A bound listener and a shutdown future.

The factory runs on the connection's own thread, so your elements don't need to
be `Send`.

## Your app

A `Tree` works as an app directly and closes the connection on Ctrl+C. For
more control, implement `App`:

- `frame(width, height)` returns the frame to draw.
- `event(event)` handles input. Return `false` to close the connection.

`peer.waker` asks for a new frame from any thread, for background work that
finishes while the app is idle.

## Limits

| Limit | Default |
| --- | --- |
| Connections | 32, set with `connections` |
| Idle timeout | 5 minutes, set with `inactivity` |
| Terminal size | 512 columns, 256 rows, 65,536 cells |
| Unread input | 1 MiB, then the connection closes |
| Blocked output | 5 seconds, then the session ends |

Clients must request a PTY. Commands, port forwarding, and subsystems are not
supported. A slow client gets only the newest frame, so it never falls behind.
