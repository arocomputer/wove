Wove is four libraries. Core has no dependency on the other three.

| Library | Owns |
| --- | --- |
| Core | Elements, layout, input, text editing, rendering, and the local terminal |
| Dioxus | Components and signals, mapped onto a core tree |
| Keymap | Key bindings, sequences, and timeouts |
| SSH | SSH connections, authentication, and one app per connection |

The library sets no application policy. It binds no quit key, runs no
executor, and never reads the clipboard.

## From tree to terminal

1. A `Tree` owns elements, their handlers, and focus.
2. Taffy lays the tree out in cells. Elements report their own size.
3. The paint pass draws each element through a clipped `Canvas` into a
   `Buffer` of cells.
4. A `Renderer` compares the buffer with the last frame and writes only the
   changed cells, as one synchronized update.

An unchanged tree returns its last frame, and the renderer skips a frame it has
already drawn. A repaint that doesn't move anything reuses the last layout.

## Ownership

- A node owns its element's state. Moving a node keeps the state. Removing it
  drops the node, its children, and their handlers.
- Hidden and detached nodes don't paint, take focus, or receive clicks.
- Core events carry no backend types. The same `Event` comes from a local
  terminal, SSH, or a test.
- Text can't emit terminal control sequences. Only the terminal and SSH
  backends write protocol bytes.

## Bytes in, bytes out

`Renderer`, `Inline`, and `input::Decoder` work on plain bytes with no
terminal attached. The optional `terminal` feature wraps them around a local
terminal with crossterm. SSH wraps them around an SSH channel.

`Inline` draws frames of any height on the main screen. Rows that scroll off
the top belong to the terminal and are never rewritten.

## Restoring the terminal

A session registers its cleanup as it turns each mode on. The session, the
panic hook, and the signal handler share that state, so the terminal is
restored exactly once however the process ends. Each frame goes out in a single
write, so a restore can't land inside one.

## Adapters

Dioxus handles components and reconciliation. The adapter turns its mutations
into public tree calls, the same ones any app can make. A failed mutation
invalidates the view, so a partial update never goes unnoticed.

The SSH library runs each app on its own thread, so core elements never need to be
`Send`. It bounds input, output waits, and terminal size.

## Where the code lives

| Path | Contents |
| --- | --- |
| `crates/core/src/element.rs` | The `Element` trait |
| `crates/core/src/tree/` | Nodes, focus, input routing, layout, and paint |
| `crates/core/src/elements/` | Built-in elements |
| `crates/core/src/text/` | Editing, undo, and text layout |
| `crates/core/src/render/` | Cells, styles, drawing, and byte output |
| `crates/core/src/terminal/` | The local terminal session |
| `crates/dioxus/src/` | The Dioxus adapter |
| `crates/ssh/src/` | The SSH server and runtime |
