Wove's built-in elements live in `wove::elements`. Every element is a plain
struct: build it, add it to the [tree](/docs/ui/#the-tree), and change its
fields with `tree.update`.

## Text

`Text` shows a string in one style. `RichText` shows styled spans.

```rust
use wove::elements::Text;

let id = tree.add(tree.root(), Text::new("Hello"))?;
```

### Wrapping

Text is clipped at the edge by default. Set `wrap` to break it onto new lines:

```rust
tree.add(tree.root(), Text {
    content: long_string,
    wrap: true,
    ..Text::default()
})?;
```

`Text` breaks at any character. `RichText` takes a `Wrap` mode: `None`,
`Character`, or `Word`. Neither ever splits a grapheme, so emoji and combined
characters stay whole. Tabs expand to stops every four columns.

`RichText` holds [styled spans](/docs/ui/#styled-runs) and links.

### Changing text

Update the fields with `tree.update`:

```rust
tree.update::<Text>(id, |text| text.content = "Bye".into())?;
```

Wove keeps the wrapped layout between frames and rebuilds it only when a field
changes.

Text can't write terminal control sequences. Control characters are removed
before painting.

## Input and Textarea

`Input` edits one line. `Textarea` edits many. Both need focus to receive keys.

```rust
use wove::elements::Input;

let name = tree.add(tree.root(), Input {
    placeholder: "Your name".into(),
    ..Input::default()
})?;
tree.focus(Some(name))?;
```

Read the value through the editor:

```rust
let value = tree.get::<Input>(name)?.editor.text();
```

### Input options

| Field | Effect |
| --- | --- |
| `placeholder` | Shown while the value is empty. |
| `mask` | Shows this character in place of each one typed, for passwords. |
| `limit` | The most characters the input accepts. |
| `cursor` | The cursor shape. |

A pasted newline becomes a space.

### Textarea

```rust
use wove::elements::Textarea;

tree.add(tree.root(), Textarea {
    wrap: true,
    ..Textarea::new("First line\nSecond line")
})?;
```

The `editor` example is a `Textarea` with a status line:

<Frame name="editor-resized" command="cargo run -p wove-examples --bin editor" />

Without `wrap`, long lines scroll sideways. With it, lines break at words and
Up and Down move through the wrapped rows.

### Keys

| Keys | Action |
| --- | --- |
| Arrows, Home, End | Move |
| Ctrl or Alt with arrows | Move by word |
| Shift with any movement | Select |
| Ctrl+A | Select all |
| Ctrl+W, Alt+Backspace | Delete a word |
| Ctrl+K, Ctrl+U | Delete to the end or start of the line |
| Ctrl+Z | Undo |
| Ctrl+Y, Ctrl+Shift+Z | Redo |

A click places the cursor. Shift+click and dragging select.

### Custom bindings

Edits are values. `text::command` turns an event into a `Command` under the
default bindings, and `Editor::apply` runs one. To use your own keys, handle
them first in a [handler](/docs/ui/#events-and-focus) and apply the command you
want.

### Atoms

An atom is a run of text that acts as one character, such as a collapsed paste
shown as `[pasted 40 lines]`. Add one with `Editor::insert_atom` and your own
id. The cursor steps over it, an edit that touches it removes it whole, and undo
brings it back. Style atoms with `Textarea::atom`.

### Undo

Undo keeps the last 100 edits. A typed word and the space after it count as
one edit.

## List and Table

A `List` shows one styled line per row. A `Table` shows columns with a header.
Both ask only for the rows in view, so they handle long data cheaply.

```rust
use wove::{elements::List, text::Span, Style};

let names = vec!["Ada", "Grace", "Linus"];
let rows = names.clone();
let list = tree.add(tree.root(), List::new(names.len(), 16, move |i| {
    vec![Span::new(rows[i], Style::default())]
}))?;
tree.focus(Some(list))?;
```

`List::new` takes the row count, the width in cells, and a function that
returns row `i`. Your app keeps the data. When it changes, update `count`:

```rust
tree.update::<List>(list, |list| list.count = 2)?;
```

### Table

```rust
use wove::elements::Table;

let table = tree.add(tree.root(), Table::new(
    vec![("Name".into(), 12), ("Role".into(), 16)],
    vec![
        vec!["Ada".into(), "Engineer".into()],
        vec!["Grace".into(), "Admiral".into()],
    ],
))?;
```

Each column is a header and a width in cells. Values that don't fit are cut.
The header stays in place while the rows scroll.

### Selection

Read the selected row from `selected`. Style it with `highlight`.

Both elements handle the arrows, Page Up and Page Down, Home, End, the mouse
wheel, and clicks. The view only moves when the selection leaves it, so a click
never slides rows under the pointer.

## Panel and Container

A `Container` groups children and draws nothing. Use it for rows, columns, and
grids.

A `Panel` draws a border around its children, with an optional title.

```rust
use wove::{elements::{Panel, Text}, Border};

let panel = tree.add(tree.root(), Panel {
    title: "Settings".into(),
    border: Border::Rounded,
    ..Panel::default()
})?;
tree.add(panel, Text::new("Inside the border"))?;
```

The border styles are `Single`, `Rounded`, `Double`, and `Heavy`. A long title
is cut to fit.

### Background

A background color in `style` fills the panel. A filled panel covers whatever
it overlaps, which is what a menu or a dialog needs. See
[overlays](/docs/ui/#overlays).

### Layout

A panel's default layout reserves one cell on each edge for the border. Start
from `tree.layout(panel)?.clone()` when you change it, or the border will draw
over your content.

## Scroll

A `Scroll` clips its children to its size and scrolls them.

```rust
use wove::{elements::{Scroll, Text}, Style};

let scroll = tree.add(tree.root(), Scroll::with_bar(Style::default()))?;
let mut layout = tree.layout(scroll)?.clone();
layout.flex_grow = 1.0;
tree.set_layout(scroll, layout)?;

for line in lines {
    let text = tree.add(scroll, Text::new(line))?;
    let mut layout = tree.layout(text)?.clone();
    layout.flex_shrink = 0.0;
    tree.set_layout(text, layout)?;
}
```

Set `flex_shrink: 0.0` on children so they keep their full height. Without it,
they shrink to fit the viewport.

`Scroll::default()` has no scrollbar. `Scroll::with_bar` adds one in its own
column, hidden while everything fits.

### Scrolling

A focused `Scroll` handles the arrows, Page Up and Page Down, Home, End, and the
mouse wheel. It also scrolls to show a child that gets focus.

End turns on `follow`, which keeps the view at the bottom as content grows.
Scrolling away turns it off. Set `offset` and `follow` yourself to scroll from
code.

### Long content

Children out of view are not painted, and content can be far taller than the
screen. Layout still visits every child, though. For thousands of entries, use
[Feed or Lazy](#feed-and-lazy).

## Feed and Lazy

A `Feed` and a `Lazy` both show long content, such as a log or a conversation.
They lay out only what is on screen, so a frame costs the same with ten entries
or ten thousand.

| Use | When each entry is |
| --- | --- |
| `Feed` | Styled text. Fastest. |
| `Lazy` | A subtree of elements, such as a message with a header and buttons. |

### Feed

```rust
use wove::{elements::Feed, text::{Span, Wrap}};

let feed = tree.add(tree.root(), Feed::new(1))?;
tree.update::<Feed>(feed, |feed| {
    feed.push(vec![Span::new("Hello", Style::default())], Wrap::Word);
})?;
```

`Feed::new` takes the blank rows between blocks. `push` adds a block and
returns its index. `set` replaces a block, which suits text that is still
streaming in, and relays out only that block.

A feed follows its tail until the user scrolls away. It then holds its place
while new blocks arrive. `follow` returns to the tail.

### Lazy

```rust
use wove::elements::Lazy;

let mut lazy = Lazy::default();
lazy.follow = true;
let column = tree.add(tree.root(), lazy)?;

for message in messages {
    let entry = tree.add(column, Panel {
        title: message.author,
        ..Panel::default()
    })?;
    tree.add(entry, Text { wrap: true, ..Text::new(message.body) })?;
}
```

Children of a `Lazy` are ordinary elements. Each one is laid out alone, at the
column's width, and only when it comes into view. Its layout is kept until
something in it changes. A child out of view isn't painted and can't be
clicked, but it stays in the focus order. Focusing it scrolls it into view.

A child takes its height from its content. Percentage heights and
`flex_grow` have nothing to fill.

### Height

Neither has a height of its own. They fill the space their parent gives them.
In an [inline session](/docs/running/#inline-mode), where frames take their natural
height, set a height in the layout.

## Markdown, syntax, and diffs

Three optional Core features turn text into a `RichText` element. Enable
only the ones you use:

```toml
[dependencies]
wove = { git = "https://github.com/arocomputer/wove", features = ["markdown"] }
```

Each works without the others, and without the terminal backend.

### Markdown

```rust
use wove::markdown::{render, Palette};

let palette = Palette {
    heading: Style { bold: true, ..Style::default() },
    ..Palette::default()
};
tree.add(tree.root(), render("# Title\n\nSome *text*.", palette))?;
```

`Palette` sets the style of `text`, `heading`, `code`, and `link`. Links open
in terminals that support them. Tables are not supported yet, and HTML shows as
plain text.

### Syntax highlighting

```rust
use wove::syntax::{Highlighter, Syntaxes, ThemeSet};

let theme = ThemeSet::load_defaults().themes["base16-ocean.dark"].clone();
let highlighter = Highlighter::new(Syntaxes::load_defaults_newlines(), theme);
tree.add(tree.root(), highlighter.highlight(source, "rs")?)?;
```

Pass a language name or file extension. Unknown languages stay plain. Reuse
one `Highlighter` for every document. Spans have no background, so fill the
parent with the theme's background color if you want it.

### Diffs

```rust
use wove::diff::render;

let added = Style { fg: Color::Indexed(2), ..Style::default() };
let removed = Style { fg: Color::Indexed(1), ..Style::default() };
tree.add(tree.root(), render(before, after, Style::default(), added, removed))?;
```

The diff has one row per line, styled as unchanged, added, or removed.

### Updating

Parsing happens when you call `render` or `highlight`. When the source changes,
render again and replace the element's `spans` with `tree.update`.

## Custom elements

Any type that implements `Element` can go in a tree. There is no registration.

```rust
use wove::{Canvas, Element, Event, Key, Response, Style};

struct Counter(i32);

impl Element for Counter {
    fn measure(&self, _width: Option<u16>) -> (u16, u16) {
        (12, 1)
    }
    fn paint(&self, canvas: &mut Canvas<'_>) {
        let text = format!("Count: {}", self.0);
        canvas.text(0, 0, &text, Style::default());
    }
    fn focusable(&self) -> bool {
        true
    }
    fn event(&mut self, event: &Event) -> Response {
        match event {
            Event::Key(Key::Up, _) => self.0 += 1,
            Event::Key(Key::Down, _) => self.0 -= 1,
            _ => return Response::IGNORE,
        }
        Response::REPAINT
    }
}
```

Every method has a default, so implement only what you need.

### Measure

`measure` returns the size the element wants, in cells, for a given width.
Use `render::columns` to count the cells a string takes, and `render::fit` to
cut it to a width. Measure the same way you paint.

### Paint

`paint` draws through a `Canvas` that covers the element's area. Anything
outside is clipped. The canvas also expands tabs and removes control
characters. `fill` sets a background, `border` draws a border, `cursor` places
the cursor, and `link` draws a hyperlink.

A tall element can check `canvas.visible_rows()` and draw only those rows.
`paint` isn't called at all while nothing of the element is visible.

### Handle events

`event` receives input after any [handler](/docs/ui/#events-and-focus) on the
node. Mouse positions are relative to the element's top-left cell. Return the
right [response](/docs/ui/#handlers) so the tree knows whether to
paint or lay out again.

### Scrolling elements

A scrolling element implements `viewport`, which runs just before `paint` with
the element's size, and `reveal`, which asks it to show a child that got focus.
`overlay` draws over the children, the way `Scroll` draws its bar. Read
`scroll.rs` in the core crate for a full example.
