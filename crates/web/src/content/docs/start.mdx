Use Rust 1.98 or newer. The current 0.0.1 source is not yet published; the earlier
0.2.0 crate has been yanked.
The optional `wove-dioxus` adapter currently requires a local checkout.
Their Rust imports are `wove` and `wove_dioxus`.

```toml
[dependencies]
wove = { git = "https://github.com/intuitums/wove", branch = "main", version = "0.0.1" }
```

## Build a tree

```rust
use wove::{Tree, elements::{Input, Text}, terminal};

fn main() -> Result<(), Box<dyn std::error::Error>> {
    let mut tree = Tree::new();
    tree.add(tree.root(), Text::new("Your name"))?;
    let input = tree.add(tree.root(), Input::default())?;
    tree.focus(Some(input))?;
    terminal::run(&mut tree, |_, event, _| *event != wove::Key::Escape.into())?;
    Ok(())
}
```

`add` attaches an element; `create` leaves it detached. `append` and `insert` move
existing elements without losing state. `update` changes typed element state and
invalidates layout and paint. `remove` drops a subtree. IDs cannot be reused or
passed to another tree.

The root fills the frame and arranges children in a column. Set a node's `Layout`
using the types in `wove::layout` for flex, grid, spacing, and alignment.
Lengths are terminal cells. `Panel` reserves its border in its default layout;
when replacing a layout, start from `tree.layout(id)?.clone()` to retain defaults.
Text defaults to clipping. Set `Text::wrap` for hard wrapping at grapheme boundaries.
Tabs expand to stops every four columns.

A `Style` sets colors, bold, dim, italic, underline, strikethrough, and reverse.
A `Color::Default` background keeps whatever is painted beneath, so text over a
filled parent does not punch a hole in it; `Color::Reset` forces the terminal
default. `Span::link` and `Canvas::link` make text open a URL in terminals with
hyperlinks.

## Input and rendering

`Tree::on` runs before an element's default behavior. `Response::HANDLED` consumes
the event; otherwise it bubbles through parents. Tab and Shift-Tab move focus
when no handler consumes the key. Mouse presses focus the nearest focusable
ancestor of the hit element. Hit testing uses the last painted frame.

`Input` supports arrows, Shift selection, Home, End, Backspace, Delete, Ctrl-A,
Ctrl-Z, Ctrl-Y, word movement and deletion, and bracketed paste. Programmatic
changes through its public editor should contain single-line text. `Editor`
itself accepts arbitrary text; it is also available to custom elements.

Mouse events carry their button and modifiers, and distinguish a drag from
plain motion. Handlers and elements see positions relative to their own
top-left cell. Modifiers include `meta` for Super or Command, which terminals
report only when `Options::keyboard` is on.

`Scroll` clips children and handles arrows, paging, Home, End, and mouse wheels.
Children that should retain their full content height need `flex_shrink: 0.0`.
End enables following; moving away from the end stops it. Children outside the
viewport are not painted, and content may be taller than 65,535 rows.

`frame` recomputes after updates or resize and otherwise returns the cached frame.
`Renderer` writes changed cells and the cursor position as one synchronized
update, and maps colors to the `Depth` the terminal accepts. `terminal::run` is a
blocking convenience loop that ends when its callback returns false; the library
binds no quit key. Applications with timers or background work can use
`Terminal`, `read`, and `poll` in their own loop. Do not print over a live
session without invalidating its renderer.

`Terminal::with_options` chooses the screen and which input modes to enable:
mouse reporting, bracketed paste, focus reports, and unambiguous key reports.
Turn `mouse` off to leave text selection to the terminal. `Terminal::background`
asks the terminal for its background color, for choosing a light or dark palette.

## Inline sessions

`ScreenMode::Inline` draws on the main screen, starting at the shell's cursor.
A frame may be of any height: ask `Tree::height` for the content's natural
height, then pass it to `frame`. When a frame outgrows the screen its head
scrolls into the terminal's own scrollback and is never rewritten.

```rust
let (width, _) = terminal.size()?;
let height = tree.height(width)?;
terminal.draw(tree.frame(width, height)?)?;
```

`Terminal::commit(rows)` releases finished rows at the top of the last frame.
They stay where they are, and the next frame starts beneath them, so remove
their elements from the tree. This keeps frames small however long a session
runs. After a resize the visible screen is cleared and the current frame is
repainted; committed rows that were still visible are gone unless the
application draws and commits them again. `Terminal::switch` moves between an
inline session and a full-screen view while running. The `inline` example shows
the whole loop.

## Test without a terminal

```rust
use wove::{testing::Screen, elements::Input, Key};

let mut screen = Screen::new(20, 3);
let input = screen.tree.add(screen.tree.root(), Input::default())?;
screen.tree.focus(Some(input))?;
screen.send(Key::Char('界'))?;
assert_eq!(screen.frame()?.cell(0, 0).unwrap().symbol(), "界");
# Ok::<(), wove::Error>(())
```

Headless tests use the same layout, elements, clipping, and input routing as a
terminal session. Real PTY checks run through `./x ui` on Unix.

## Multiline and styled text

`Textarea` edits multiple lines with vertical cursor movement and a scrolling
viewport; `wrap` breaks long lines at words. `RichText` uses styled `Span` values and `Wrap::Word` for word wrapping.
See [elements and text](/docs/elements/) for details.
