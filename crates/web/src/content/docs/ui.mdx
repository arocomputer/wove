Every Wove app is a tree of elements. This page covers how you build the tree,
arrange it, style it, and respond to input.

## The tree

A `Tree` holds every element in your app. You get an `Id` for each one, and the
tree owns its state.

```rust
let mut tree = Tree::new();
let list = tree.add(tree.root(), Container)?;
let item = tree.add(list, Text::new("First"))?;
```

### Add and create

`add` creates an element and attaches it under a parent. `create` makes one
without a parent. Attach it later with `append` or `insert`:

```rust
let item = tree.create(Text::new("Later"))?;
tree.insert(list, item, 0)?;
```

### Read and update

`get` borrows an element by type. `update` changes it and tells the tree to lay
out and paint again:

```rust
tree.update::<Text>(item, |text| text.content = "Updated".into())?;
let content = &tree.get::<Text>(item)?.content;
```

Asking for the wrong type returns `Error::WrongType`.

### Move and remove

`append` and `insert` also move an element that is already attached. The
element keeps its state, so a moved input keeps its text, cursor, and undo
history.

`remove` drops the element, its children, and their event handlers. An `Id`
is never reused, and it only works with the tree that made it.

### Draw a frame

`tree.frame(width, height)` lays out the tree and returns a `Buffer` of cells.
If nothing changed since the last call, it returns the same frame without doing
any work. `terminal::run` calls it for you. You call it yourself when you write
your own loop or test without a terminal.

## Layout

Wove uses [Taffy](https://github.com/DioxusLabs/taffy) for flexbox and grid
layout. Every length is a number of terminal cells.

```rust
use wove::{elements::{Container, Text}, layout::*, Layout, Tree};

let mut tree = Tree::new();
let row = tree.add(tree.root(), Container)?;
tree.set_layout(row, Layout {
    flex_direction: FlexDirection::Row,
    gap: Size { width: length(2.0), height: zero() },
    ..Layout::default()
})?;
tree.add(row, Text::new("Left"))?;
tree.add(row, Text::new("Right"))?;
```

`wove::Layout` is Taffy's `Style`. `wove::layout` re-exports Taffy's helpers,
such as `length`, `percent`, `Size`, and `FlexDirection`.

### The root

The root fills the frame and stacks its children in a column.

### Keep an element's defaults

Some elements come with a layout. A `Panel` reserves one cell on each edge for
its border. `set_layout` replaces the whole layout, so start from the current
one when you only want to change a field:

```rust
let mut layout = tree.layout(panel)?.clone();
layout.flex_grow = 1.0;
tree.set_layout(panel, layout)?;
```

### Fill the remaining space

Give an element `flex_grow: 1.0` to take the space its siblings leave. A child
of a flex container can also shrink below its content. Set `flex_shrink: 0.0`
to keep its full height, which you usually want for children of a
[`Scroll`](/docs/elements/#scroll).

### Overlays

Set `position: Position::Absolute` to take an element out of the flow, then
raise it with `Tree::set_z`. Siblings paint in ascending `z`, and the mouse hits
the top one first. A `Panel` with a background color covers what is beneath it,
which suits menus and dialogs.

## Styling

A `Style` sets colors and text attributes. Every field has a default, so set
only what you need:

```rust
use wove::{Color, Style};

let title = Style {
    fg: Color::Rgb(104, 211, 192),
    bold: true,
    ..Style::default()
};
```

The attributes are `bold`, `dim`, `italic`, `underline`, `strikethrough`, and
`reverse`.

### Colors

| Color | Meaning |
| --- | --- |
| `Default` | No color. A background keeps whatever is painted beneath. |
| `Reset` | The terminal's default color, covering anything beneath. |
| `Indexed(n)` | A color from the terminal's 256-color palette. |
| `Rgb(r, g, b)` | A true color. |

`Default` is what lets text sit on a filled panel without cutting a hole in it.
Terminals with fewer colors get the nearest match.

### Styled runs

A `Span` is text with one style. Put several in a `RichText` to mix styles in
one block:

```rust
use wove::{elements::RichText, text::{Span, Wrap}};

let line = RichText::new(vec![
    Span::new("error: ", Style { fg: Color::Indexed(1), ..Style::default() }),
    Span::new("file not found", Style::default()),
], Wrap::Word);
```

### Links

`Span::link` makes text open a URL in terminals that support hyperlinks. Other
terminals show plain text.

```rust
let docs = Span::link("docs", Style::default(), "https://wovetui.com");
```

## Events and focus

Keys go to the focused element. Mouse events go to the element under the
pointer. Either way, the event then bubbles up through its parents.

```rust
use wove::{Event, Key, Response};

tree.on(input, move |event| match event {
    Event::Key(Key::Enter, _) => {
        // Submit the form.
        Response::HANDLED
    }
    _ => Response::IGNORE,
})?;
```

### Handlers

`Tree::on` attaches a handler to a node. It runs before the element's own
behavior. Return one of these:

| Response | Meaning |
| --- | --- |
| `IGNORE` | Not handled. The element and its parents get the event. |
| `HANDLED` | Stop here. Nothing on screen changed. |
| `REPAINT` | Stop here and paint again. |
| `CHANGED` | Stop here, lay out, and paint again. |

Use `CHANGED` only when something can change size. Layout visits the whole
tree, so a cursor move or a scroll should return `REPAINT`.

### Keys

`Event::Key` carries a `Key` and `Modifiers`. A letter already includes Shift,
so Shift+g arrives as `Key::Char('G')` with no `shift` flag. That holds for a
local terminal, SSH, and kitty key reports alike. Build key events with
`Event::key` to get the same form.

### Focus

`tree.focus(Some(id))` focuses an element. Tab and Shift+Tab move focus in
child order when no handler takes the key. A click focuses the nearest element
that accepts focus. A `Scroll` or `Lazy` scrolls to show whatever gets focus.

Elements receive `Event::Focus` and `Event::Blur`. `Event::WindowFocus` is
different: it reports the terminal window itself.

### Mouse

Mouse positions are relative to the receiving element's top-left cell, so a
handler never needs to know where the element was laid out. The element that
handles a press keeps the pointer until release, even when a drag leaves it.

`Event::Enter` and `Event::Leave` report the pointer crossing an element. They
need `Options::motion`, which is off by default.

### Text selection

Capturing the mouse takes away the terminal's own selection, so Wove adds one
back. Dragging on anything that doesn't handle the press selects text on
screen. Read it with `Tree::selected_text`, and copy it with `Terminal::copy`.
You decide when to copy, on release or on a key. Turn selection off with
`Tree::set_selectable(false)`.
